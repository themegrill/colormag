## How the options are implemented

- **Settings framework:** **Customind**, a proprietary React app vendored at
  `inc/customizer/customind/` (`core/Customind.php`, build output
  `build/customind.js`). Option definitions are PHP arrays under
  `inc/customizer/options/`, not `$wp_customize->add_*` calls — a repo-wide
  grep for `$wp_customize->add_` returns **1 hit**, confirming the raw
  Customizer API is essentially unused.
- **Two code paths — yes.** Theme mod `colormag_enable_builder` switches the
  entire header/footer settings surface between the drag-and-drop builder and
  the legacy panels (`inc/migration/`, 19 hits for
  `colormag_maybe_enable_builder`). New installs get the builder; existing
  sites are migrated onto it by
  `colormag_free_major_update_customizer_migration_v1`.
- **Pro-gating:** present in the builder component lists (Divider, Off Canvas,
  Color Switcher, Footer Logo/Button). A free build sees these absent or
  disabled.

## Findings this source pass turned up (not in the handbook)

**1. `current_user_can( 'activate_plugin' )` — capability does not exist.**
`inc/admin/class-colormag-welcome-notice.php:148` and `:189`. WordPress's
capability is `activate_plugins` (plural); the theme's own REST endpoint
uses the correct plural form at functions.php:369. An unknown capability
returns false for every non-super-admin, so on a single-site install the
"Let's Get Started" flow would install the demo importer, skip the
activation branch entirely, and redirect to a starter-templates page for a
plugin that is still inactive. Would appear to work on multisite (super
admins pass every cap), which is a classic reason this survives review.
**Needs live verification before filing** — the redirect target
(`themes.php?page=tg-starter-templates`) may itself trigger activation.

**2. `header-sidebar-1` is referenced but never registered.**
`inc/customizer/class-colormag-customizer.php:97` lists it among the header
widget areas to be re-panelled into the header builder, but it is the only
occurrence in the entire codebase — `colormag_builder_widget_init()`
(class-colormag-widgets.php:280-302) registers only `header-sidebar-2`
("Widget Two"). Either a "Widget One" component was removed and this is a
leftover, or a widget area is missing behind a builder component. Harmless
if vestigial. **Needs a live look at the header builder's component list.**

Both are candidates, not confirmed bugs. Neither has been exercised in a browser.
